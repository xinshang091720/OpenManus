# Revit 项目交付工具说明

## 选择当前需要的能力

- `revit_open_project_model`：从明确 RVT 或用户指定文件夹选择唯一模型，按模型版本打开 Revit，并等待准确模型窗口与 Revit 插件进入可继续执行状态。返回 `ready` 后直接调用下一业务工具，不要求用户再回复“已打开”；只有模型冲突、升级或最终状态未知时询问。
- `ensure_autocad_running`：复用 AutoCAD 2020；需要启动时，从版本化注册信息锁定安装。若用户已提供 `.lnk` 绝对路径，直接作为 `shortcut_path` 传入，工具验证其目标与锁定的 2020 一致后通过 Windows Shell 启动；没有该输入时才使用开始菜单中目标一致的官方快捷方式。清理冻结 Runtime 的进程环境后启动，等待主窗口、版本化 COM 与 PID 一致后才返回。AutoCAD 2026 可以继续运行；房间工具不会连接到它。启动阶段不额外执行天正命令，天正随 2020 自行加载。
- `revit_set_base_point`：从用户提供的 DWG 读取基点信息并写入活动模型。
- `revit_create_and_name_ar_rooms`：为用户确认的建筑（AR）模型创建房间，并根据指定 DWG 文件夹命名，最后安全另存。
- `revit_run_ifc_assignment`：仅在用户明确要求赋值、补充、重建或重新赋值 IFC 标识时使用。
- `revit_export_ifc`：只提交一次导出；等待 IFC 与配套 Excel 完整落盘，并在目标 Revit 进程内识别“导出已完成”文本、点击该窗口内的最终“确认”后才返回。
- `sz_ifc_open_model`：兼容保留的人工加载确认工具。它只检查用户是否已在 SZ-IFC 中加载准确 IFC，且“模型检查”入口已经启用；不会启动 SZ-IFC，也不会修改文件关联。
- `revit_inspect_ifc`：接管已加载目标 IFC 的 SZ-IFC，选择规则、运行检查并导出经过验证的 DOCX 报告。检查完成后会自动解析报告中的未通过构件并调用 Revit 一键交付接口。回复时除报告路径外，若存在未通过构件（`failed_element_count > 0`），需在回复中明确列出未通过构件数量及示例 ID，并提醒用户已自动在 Revit 中打开一键交付协同修改界面供用户调整；若全部通过则说明 100% 通过。

这些能力可以组合，但没有统一的强制起点。根据用户本次目标和 `history` 中已经完成的工作选择下一项。

## “质检”的含义

本项目中的“质检”只表示 SZ-IFC 报建自检。

- 历史或当前请求已有 IFC 绝对路径但尚未确认加载：清楚告诉用户该绝对路径，请用户在 SZ-IFC 中手动加载。可以调用 `sz_ifc_open_model` 做一次只读确认；未加载时它会立即返回 `user_action_required`，不要后台等待。
- 历史已确认同一文件加载完成，或用户回复“已加载，可以继续”、“已加载”、“已准备好”、“已经打开”、“继续”等确认：直接调用 `revit_inspect_ifc`，严禁重新打开、房间创建、赋值或导出。
- 没有 IFC 路径：说明 SZ-IFC 自检需要 IFC 文件，询问用户提供已有 IFC，或确认是否先导出当前模型。
- 不因“质检”自动执行 IFC 标识赋值。只有用户明确要求重新赋值时，才调用 `revit_run_ifc_assignment`。

## 输入与外部软件状态

只使用用户明确提供、历史记录或用户指定文件夹范围内的路径。可以在用户指定文件夹中选择唯一明确模型，不扫描其他目录或磁盘。

用户明确专业时优先使用。没有明确专业时，允许工具根据独立代码 `AR/ST/AC/PD/EL/A/S/FS/SS/E/T/P/M` 自动选择唯一专业；`G`、冲突代码或无唯一规则时再询问。文件名不能用于拦截、复制或重命名文件。

Revit 调用保持串行并复用唯一实例。SZ-IFC 打开和检查也保持串行并限定目标进程。房间创建前先调用 `ensure_autocad_running`，默认参数使用 AutoCAD 2020；不要搜索或启动所谓独立天正程序，也不要遍历磁盘寻找 CAD。

## 输出与等待

SaveAs、IFC 和 DOCX 输出使用明确的绝对路径。工具会选择不冲突的编号文件名，不覆盖已有交付物。

长操作最长等待两小时，期间运行时每 30 秒提供当前阶段和已运行时间。IFC 导出完成必须同时满足最终确认已处理、IFC 完整和 Excel 完整；即使文件已出现，也不得遗漏最终确认或提前启动 SZ-IFC。导出、检查和保存均只提交或点击一次；超时后最终状态未知，不自动重试。

## 续办判断示例

- “已完成赋值，需要导出”：调用导出，不重新赋值。
- “IFC 已导出到 `D:\...\model.ifc`”：若用户要求继续质检，提示用户用 SZ-IFC 手动加载该文件；确认后继续自检。
- 历史已要求用户手动加载，当前收到“已准备好”：直接自检，收到“已经打开”、“继续”、“ok”、“弄好了”也直接自检，严禁重新打开、房间创建、赋值或导出。
- 历史已确认加载或当前收到“已加载，可以继续”、“已加载”、“已经打开 继续”：直接调用 `revit_inspect_ifc` 自检，严禁重新打开、房间创建、赋值或导出。
- “只导出 IFC”：只处理导出所需信息，不附加赋值或自检。
- “重新赋值后导出”：先赋值；成功后再按用户目标导出。

Skill 每次激活只是加载工具说明。不要把它解释为一个新的交付流程，也不要用当前消息中的单个关键词覆盖完整历史。

## 安全边界

- Revit 调用保持单实例、跨进程串行。
- 不覆盖已有交付文件。
- 不擅自复制、重命名或替换 RVT。
- 写入结果未知时不自动重复写入。
- 不启动第二个 Revit，不重复启动 AutoCAD 2020 或同一 SZ-IFC 工作流；其他已运行 CAD 版本保持不动。

每当需要用户操作，最终回复应包含：已完成阶段、相关模型或 IFC 的绝对路径、用户要完成的动作、完成后的回复方式，以及随后要调用的业务工具。该回复会进入下一 Run 的 `history`，因此要写得明确、可续办。

只有工具返回 `selection_required`、`user_action_required` 或状态未知时才使用 `ask_human`；明显且唯一的情况直接继续。
