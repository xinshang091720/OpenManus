# Revit 房间创建与同步说明

## 工具用途

`revit_create_and_name_ar_rooms` 面向建筑（AR）模型：读取指定文件夹内可识别楼层的 DWG，预检坐标平移，批量创建房间，写入房间名，并安全另存模型。它返回 `saved_model_path` 和审计记录路径。

`revit_preview_room_sync` / `revit_apply_room_sync` 是旧版两步工具，只适合用户明确要求先预览一张 DWG 的坐标和房间数据，再确认写入已有房间的场景。预览不写模型；应用不创建房间。

## 使用前需要的信息

- 用户明确提供 RVT、DWG 文件夹或包含模型的项目文件夹路径。
- 用户明确说明建筑专业时直接采用；否则唯一的 `AR`/`A` 独立代码可作为自动选择依据。多个候选或专业冲突时再询问。
- Revit 与项目插件已可用。
- 如果本次调用 `revit_open_project_model` 返回 `ready`，表示目标模型和插件已可以接受下一操作；直接继续 AutoCAD 就绪和房间创建，不要求用户再确认模型已打开。
- 组合房间工具运行前先调用 `ensure_autocad_running`，默认启动或复用 AutoCAD 2020。即使 2026 已运行也保留它，并行启动 2020；房间自动化只绑定 `AutoCAD.Application.23.1` 及对应 PID。若用户已提供 AutoCAD 2020 的 `.lnk` 绝对路径，直接将该路径传入 `shortcut_path`；工具会验证快捷方式目标是否为注册表定位的 2020，再通过 Windows Shell 启动，不要重新浏览项目文件夹或另找快捷方式。没有该输入时，工具才读取开始菜单中目标一致的官方快捷方式。清理冻结 Runtime 的进程环境后启动，并在主窗口、版本化 COM 和 PID 全部一致后才返回就绪。AutoCAD 启动时会自行加载已安装且兼容的天正插件，启动阶段不额外执行天正命令。

只有 `ensure_autocad_running` 自动启动失败，或后续天正能力不可用时，才请用户手动打开/检查安装；下一 Run 从该阶段继续。

## 工具影响与输出

组合工具会修改 Revit 模型，但不修改源 DWG。它使用已确认的仅中点平移策略，不增加旋转、缩放或单位换算硬门槛。完成后默认保存到源模型旁的 `result` 文件夹，也可以使用用户提供的安全保存目录。

该操作可能耗时较长。运行时会显示当前 DWG 序号、CAD 命令、临时 DXF、轴网、房间创建、命名和另存阶段；只保留 AutoCAD 2020 已验证需要的 2 秒文档稳定等待，其余条件满足后立即继续。达到两小时后报告最终状态未知，不自动重复创建或写入房间。

## 如何继续后续工作

房间工具成功返回 `saved_model_path` 后，把该绝对路径记录在回复中。若用户随后要求 IFC 标识赋值、导出或 SZ-IFC 自检，只执行用户当前要求且尚未完成的阶段。

不要为了后续导出重新打开原始源 RVT，否则可能丢失刚创建的房间。不要因为用户说“质检”而重新创建房间或执行 IFC 赋值。

## 安全边界

- 复用现有 Revit 和 AutoCAD 2020；其他 CAD 版本不关闭、不连接。
- 用户明确提供的 AutoCAD 2020 `.lnk` 可作为本次启动输入，但必须验证其目标与注册表定位的 2020 一致；否则只读取系统和当前用户开始菜单中的快捷方式。不遍历磁盘，也不执行指向其他安装的目标。
- 不搜索或启动独立的“天正可执行程序”。
- 不终止、重启或擅自关闭用户的 Revit/CAD 会话。
- 不覆盖已有结果模型，不修改源 DWG，不根据文件名改名或复制 RVT。
- 写入结果未知时不自动重试。

## DWG 楼层确认

处理用户指定文件夹中的全部项目 DWG；文件名仅是候选提示，不是筛选、改名或拷贝规则。优先使用用户已经确认的映射和图框/图名中的楼层信息；图名明确表示楼层范围时，按该范围处理。确实无法唯一判断时，在创建、命名或另存 Revit 之前返回 `selection_required`，一次询问用户“哪个绝对 DWG 路径对应哪些楼层”。用户确认后使用返回的 `dwg_path` 和 `floor_numbers` 作为 `floor_overrides` 续办；允许重新预检图纸，但不得重复或强制执行已未确认的 Revit 写入步骤。

需要用户操作时，最终回复记录已完成阶段、RVT/DWG 绝对路径、用户操作、确认回复方式和下一业务工具。
