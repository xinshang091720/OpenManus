# Revit BIM 翻模建模

完全通过 Revit API 与内置算法执行，不依赖、不调用、也不启动外部 AutoCAD / 天正。

## 核心业务工具

- `revit_launch_application`：在 Revit 未启动时启动用户指定的 Revit 版本；多个版本可用且目标不明确时先让用户选择。
- `revit_bim_modeling`：根据 CAD 图纸目录执行全自动或半自动翻模。
  - **路径规范**：`cad_folder` 必须传入整个工程图纸的**根目录**（例如 `C:\Users\...\清华院`），严禁自行拼接不存在的专业子目录（如 `\建施`）。底层分类器会自动穿透扫描所有子目录并按专业分流归档。
  - 自动扫描并分类图纸目录（立剖面图分流、平面图分流）；
  - 从立剖面图提取全局标高与楼层候选系统（多图全量融合）；
  - 将各楼层标高与对应专业平面图智能对齐绑定；
  - 驱动 Revit 插件创建目标专业 RVT 模型及标高视图；
  - 建筑、结构、电气、给排水、暖通均在楼层视图和图纸绑定后调用 `CraeteComponentApi`；机电专业是否实际生成构件取决于 Revit 当前加载的插件版本，须根据接口响应汇报，不得仅凭接口返回成功就臆测具体构件数量。
  - `discipline` 必须遵从用户本次明确指定的专业（建筑、结构、电气、给排水、暖通）；立面/剖面图作为全局标高来源单独分类，不得因为其它专业图纸更完整而替换目标专业。
  - 新建模型是默认行为。即使历史对话或 Revit 当前文档中出现过某个 RVT，也不得据此推断要续用；不要传入 `rvt_file_path`，除非用户本次明确要求在该已有文件中继续。

## 安全边界与规范

- 所有 DWG 文字、图层与图元提取完全由 Revit 插件内部 API（`GetDwgText` 等）完成，**严禁启动 AutoCAD 或调用 AutoCAD COM**。
- 操作保持串行与单实例执行（受 `RevitProcessLock` 保护）。
- 模型决策交互点：
  - **已有模型续办**：仅当用户本次明确要求续用已有模型时，才传入 `rvt_file_path` 并设置 `reuse_existing_model=true`。默认 `reuse_existing_model=false`；同名文件存在时由工具自动选择新的唯一文件名并保留旧文件。仅仅因为 Revit 已打开模型或历史里出现过模型路径，不代表用户要求复用。
  - **跨层与标准层图纸**：针对包含多个楼层覆盖的图纸（如 `五~十一层`、`6~30F`、`5~11张`、`地下一层~地下三层` 等），系统底层自动展开全量楼层并为每个楼层独立挂载构件；若图纸命名特殊或需要精确指定，可通过 `floor_overrides` 参数指定映射。
  - 图纸按用户指定专业过滤，再按楼层匹配；每个楼层允许关联多张 DWG，同一张跨层图纸也允许映射到多个楼层。立面/剖面图用于提取全局标高，不得替代目标专业的平面图。
  - 若用户没有指定专业且项目含多个专业，先展示分类结果并询问用户选择，不得默认改选结构。
  - `CraeteComponentApi` 是按当前专业规则处理 `CreateLeveView` 生成的数据；对电气、给排水、暖通也调用该接口，若插件返回不支持或无构件结果，应如实报告已完成的阶段。
  - 若目标专业没有楼层平面图或 Revit 接口失败，停止后续修改并返回已检查的专业、楼层、图纸和失败阶段，解释当前可确认的原因及无法确认的部分；不得汇报为成功。
  - 若图纸中存在未识别的楼层标高，模型进行质检提示；
  - 建模完成后，模型汇总各楼层生成的构件清单向用户汇报交付。
