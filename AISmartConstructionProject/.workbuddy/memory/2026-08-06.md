## 2026-08-06 CheckUpdata 类重构修复

### 问题清单（共 9 项）
1. **`IsOneVersionGreater` 比较逻辑 bug**：缺少 `==` 的 continue 判断，`1.0.5` vs `1.2.3` 误判为有更新（应为本地更旧）
2. **`ConstructionUpdate` 空引用风险**：`FirstOrDefault` 返回 null 后直接访问 `.ReleaseNumber`
3. **`AiConstructionUpdate` 同样的 null 风险**
4. **`ReleaseNumber.Split('V')` 越界风险**：不含 'V' 时 `Parts1[1]` 越界
5. **`Descendants("Assembly").First()` 异常风险**：XML 无该节点时抛异常
6. **`GetVersion()` 每次调用都发 HTTP 请求**，无缓存
7. **`InstallationPath` 硬编码 11 个 if-else**，且只返回第一个版本（2016 优先于 2020）
8. **未使用变量** `fileVersion`（L49/L74）
9. **多余 using** 语句

### 修复方案
- 重写 `IsOneVersionGreater` → `IsOnlineNewer`：优先用 `Version.TryParse` 比较，fallback 逐段比较；支持带/不带 V 前缀、2~4 段版本号
- `GetVersion` 加 5 分钟缓存（`_cachedVersions` + `_cacheTime`）
- 两个 Update 方法加 try-catch 全局保护 + null 检查
- `InstallationPath` 改为遍历目录 `Directory.GetDirectories`，新增 public `GetInstalledAddinPaths` 返回所有已安装版本
- `.First()` → `.FirstOrDefault()` + null 检查
- 删除未使用变量和多余 using
- 外部调用方法签名未变，无编译影响

### 新增：本地更新地址配置管理
- **需求**：检查更新返回 true 时保存 `ApplicationLinks` 到本地文件，false 时清空对应字段
- **实现**：
  - 配置文件路径：`AppDomain.CurrentDomain.BaseDirectory/update_links.json`
  - 配置模型 `UpdateLinksConfig`：两个字段 `ConstructionLink`、`AiConstructionLink`
  - `SaveUpdateLink(field, link)`：true 时写入地址，文件不存在则创建
  - `ClearUpdateLink(field)`：false 时清空字段，文件不存在则忽略
  - `GetUpdateLink(field)`：public 方法，供外部读取保存的地址
  - 两个 Update 方法在每个返回 false 的分支都调用 `ClearUpdateLink`，返回 true 时调用 `SaveUpdateLink`
- **修复**：`Math.Max` 笔误（`lParts` 缺少 `.Length`）改为三元运算符
