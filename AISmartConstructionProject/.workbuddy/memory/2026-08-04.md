### Services 文件夹日志去重
审查了 `LogHelper`、`RevitPortDetector`、`RevitProxyService`、`RuntimeManager` 四个文件的日志调用，删除了 3 处重复/高频刷屏日志：

1. **RevitPortDetector.cs L179** — `[端口检测] 前台非 Revit，选择最新实例...`
   - 原因：扫描定时器每 500ms 执行一次，前台非 Revit 时反复输出同一内容；端口变化时 L82 已有记录。

2. **RevitProxyService.cs L180** — `[代理服务] OpenRevitFile 请求，使用 ActivePort（不读缓存）`
   - 原因：与 L246 转发日志信息重叠，每个请求被记录两遍。

3. **RevitProxyService.cs L194** — `[代理服务] 使用模型绑定端口: ...`
   - 原因：与 L246 转发日志的端口信息重复。

保留了 L246 `[代理服务] 转发 {method} {path} → 端口 {port}` 作为唯一的请求级日志。

### SSE 日志去重 (HomeInterfaceVM.cs)
- **问题**：第 723 行对每个 SSE 事件都记录完整 `data`。Runtime 后端先推 `assistant_message`(phase=final) 携带 `content`，再推 `run_completed` 携带 `final_answer`，两者文本完全相同，导致日志中同一段长文本出现两次。
- **UI 无重复**：`HandleRunCompleted` 有 `string.IsNullOrEmpty(bubble.Content)` 保护，只有 assistant_message 未推送时才兜底。
- **修复**：`run_completed` 事件日志改为 `data=(omitted, same as assistant_message)`，不再重复输出完整文本。

### _history 历史去重 (HomeInterfaceVM.cs L751)
- **问题**：`finalAssistantContent` 在 `assistant_message`(phase=final) 和 `run_completed` 两处都被赋值，`run_completed` 用 `??` 覆盖前者，内容相同时等于存了两遍同一文本。
- **修复**：删除 L751 `finalAssistantContent = chunk;`，`finalAssistantContent` 只从 `run_completed` 的 `final_answer` 获取。`assistant_message` 仍负责 UI 显示（`AppendChunkToBubbleAsync`），`_history` 只保存 `run_completed` 的最终答案。

### AddDialogueHistory API 数据源统一 (HomeInterfaceVM.cs L851)
- **问题**：上一轮将 L850 改为优先用 `aiFullContent`（`assistant_message` 流式累积），但 `aiFullContent` 不区分 `Phase`，会把 `phase=plan`/`phase=reasoning` 等思考过程内容一起保存到后台接口。而 `_history`（L846）和 `StopCommand`（L929）都只保存 `finalAssistantContent`（`run_completed` 的 `final_answer`），三处不一致。
- **修复**：L851 改回 `finalAssistantContent`，与 `_history` 和 `StopCommand` 保持一致——三处均只保存 `run_completed` 的最终答复，不保存思考过程。
- **`aiFullContent` 仍保留**：用于 UI 气泡显示（L749-750 `AppendChunkToBubbleAsync`）和日志长度统计（L901），但不持久化到后台。
- **设计原则**：`_history` 给 BeeSync.AgentRuntime 做上下文，只需最终答复；后台 `AddDialogueHistory` 做对话记录，也只需最终答复；思考过程（plan/reasoning）仅用于 UI 展示，不持久化。
