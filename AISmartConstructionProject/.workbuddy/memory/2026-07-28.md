## Revit 多实例端口自动检测 + HTTP 代理

**问题**：Revit 插件 HTTP 端口硬编码 5000，多实例会冲突。用户不能手动选择实例。

**方案**：WPF 内置 HTTP 代理 + 前台窗口自动检测

### 新增文件
- `Services/RevitPortDetector.cs`：扫描 `%TEMP%/BeeSync/revit_ports/{PID}.port` 发现 Revit 实例，通过 `GetForegroundWindow()` 监控前台窗口自动切换活跃实例，500ms 定时扫描
- `Services/RevitProxyService.cs`：固定端口 50000 的 HTTP 代理，转发请求到当前前台 Revit 的动态端口。无 Revit 时返回 503

### 修改文件
- `RuntimeManager.cs`：`--revit-api-base-url` 和 `BEESYNC_REVIT_API_BASE_URL` 改为代理地址 `http://localhost:50000/api/RevitApi`
- `App.xaml.cs`：OnStartup 启动 PortDetector + Proxy，OnExit 停止两者

### Revit 插件端需要的改动（用户侧）
- 取消注释 `FindAvailablePort()`
- 启动时写入 `%TEMP%/BeeSync/revit_ports/{PID}.port`
- 关闭时删除该文件

## 模型-Revit 端口绑定（方案二）

**问题**：用户打开模型后，WPF 焦点在聊天窗口，点击"清空参数"时 `GetForegroundWindow()` 返回 WPF 窗口而非 Revit，导致 `ResolveActivePort()` 可能路由到错误端口或返回 null，第一次清除失败。切换到 Revit 窗口后再清除才成功。

**根因**：`RevitPortDetector.ResolveActivePort()` 在多实例时依赖 `GetForegroundWindow()` 定位前台 Revit，WPF 获得焦点时匹配失败，降级为 `.Values.First()` 可能返回错误的端口。

**实现**：修改 `RevitProxyService.cs`：
1. 新增 `_lastSuccessfulPort` 字段：缓存上次成功处理 Revit API 请求的端口
2. 新增 `ResolveTargetPort()` 方法：Revit API 请求优先使用缓存端口（验证仍存活），非 Revit 请求或无缓存时降级为 ActivePort
3. `ForwardRequest()` 重构：先读 body → 用 `ResolveTargetPort` 确定目标 → 成功后缓存端口
4. 订阅 `ActivePortChanged`：所有 Revit 退出时清除缓存
5. 新增 `IsRevitApiPath()` 判断路径是否包含 `/RevitApi`
6. 转发日志增强：记录路径 + 目标端口 + 详细错误信息

## 新 Revit 实例打开模型后清空参数失效

**问题**：已有 Revit（PID 32496）打开模型 A 并缓存端口。用户让 AI "重新打开一个 Revit"打开模型 B，AI 启动新 Revit（PID 18020）。但后续 `ClearParameters` 仍发到旧实例 32496，导致失效。

**根因**：
1. `RevitProxyService` 的缓存 `_lastSuccessfulPort` 一直指向旧实例
2. `RevitPortDetector.ResolveActivePort()` 多实例时前台不是 Revit，降级为 `.Values.First()`，可能仍返回旧实例
3. `OpenRevitFile` 请求也走缓存，新实例无法被选中

**修复**：

### `RevitPortDetector.cs`
1. 新增 `_instanceTimestamps`：记录每个 `.port` 文件的最后修改时间
2. `RefreshInstances()`：扫描时同时记录 `File.GetLastWriteTime(file)`
3. `ResolveActivePort()`：多实例前台非 Revit 时，不再返回 `.Values.First()`，而是选择**最新启动**的实例（`.port` 文件修改时间最新），确保新 Revit 能被自动路由到

### `RevitProxyService.cs`
1. `ResolveTargetPort()`：`OpenRevitFile` 请求**不使用缓存**，强制走 `ActivePort`（让新实例能被选中），成功后缓存自动更新为新端口
2. 新增 `IsOpenModelPath()` 判断路径是否包含 `OpenRevitFile`
3. 其他 Revit API 请求（如 ClearParameters）继续使用缓存，保持稳定
